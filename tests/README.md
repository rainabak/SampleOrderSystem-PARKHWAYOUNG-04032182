# 수동 테스트 시나리오 — SampleOrderSystem

자동화 테스트 없이 콘솔 조작으로 검증하는 수동 테스트 시나리오 모음입니다.

---

## 테스트 환경 준비

1. `data/` 디렉토리를 비우거나 새로 생성한다.
2. 프로그램을 실행한다.
3. 메인 메뉴 → **2. DummyData Generator** → **4. 전체 생성** 으로 초기 데이터를 준비한다.
   - 시료: 10건, 주문: 20건, 생산 라인: 20건 생성 권장 (소규모로 추적 용이)

---

## TC-01 주문 흐름 테스트

### TC-01-1 주문 정상 생성

**목적**: 주문 생성 시 RESERVED 상태로 저장되는지 확인

**절차**
1. 메인 메뉴 → 주문 관리 → 주문 생성
2. 시료 ID: 1 입력
3. 고객사명: "테스트고객" 입력
4. 수량: 5 입력

**기대 결과**
- 주문 생성 성공 메시지 표시
- 주문 목록 조회 시 해당 주문이 status=RESERVED로 존재
- `data/orders.json` 파일에 새 주문 레코드가 추가됨

---

### TC-01-2 생산 시작 (RESERVED → PRODUCING)

**목적**: 생산 시작 시 Order가 PRODUCING으로 전환되고 ProductionLine이 생성되는지 확인

**전제 조건**: TC-01-1 완료 (RESERVED 주문 존재)

**절차**
1. 주문 관리 → 생산 시작
2. RESERVED 상태 주문 ID 입력
3. 라인명 "LINE-TEST01" 입력

**기대 결과**
- 성공 메시지 표시
- 해당 주문의 status가 PRODUCING으로 변경됨
- 생산 라인 목록에 LINE-TEST01이 IDLE 상태로 추가됨
- `data/orders.json`, `data/production_lines.json` 파일 모두 반영됨

---

### TC-01-3 이미 PRODUCING 주문에 중복 생산 시작 시도

**목적**: 이미 생산 중인 주문에 대한 중복 시작 거부 확인

**전제 조건**: TC-01-2 완료 (PRODUCING 주문 존재)

**절차**
1. 주문 관리 → 생산 시작
2. PRODUCING 상태의 주문 ID 입력

**기대 결과**
- 오류 메시지 표시 (중복 생산 불가)
- 주문 상태 변화 없음
- 생산 라인 중복 생성 없음

---

### TC-01-4 주문 취소 (RESERVED → REJECTED)

**목적**: RESERVED 주문 취소 정상 처리 확인

**전제 조건**: RESERVED 상태 주문 존재

**절차**
1. 주문 관리 → 주문 취소
2. RESERVED 상태 주문 ID 입력

**기대 결과**
- 취소 성공 메시지 표시
- 해당 주문의 status가 REJECTED로 변경됨
- `data/orders.json` 파일에 반영됨

---

### TC-01-5 CONFIRMED 주문 취소 시도 (거부)

**목적**: CONFIRMED 이후 상태 주문은 취소 불가함을 확인

**전제 조건**: CONFIRMED 상태 주문 존재

**절차**
1. 주문 관리 → 주문 취소
2. CONFIRMED 상태 주문 ID 입력

**기대 결과**
- 오류 메시지 표시 (취소 불가 상태)
- 주문 상태 변화 없음

---

### TC-01-6 RELEASED 주문 상태 변경 시도 (모든 전환 거부)

**목적**: 종단 상태(RELEASED)에서 어떠한 상태 전환도 불가함을 확인

**전제 조건**: RELEASED 상태 주문 존재

**절차**
1. 주문 관리 → 생산 시작 → RELEASED 주문 ID 입력
2. 주문 관리 → 주문 취소 → RELEASED 주문 ID 입력

**기대 결과**
- 두 경우 모두 오류 메시지 표시
- 주문 상태 변화 없음

## TC-02 생산 라인 테스트

### TC-02-1 생산 라인 목록 조회

**목적**: 생산 라인 목록이 올바르게 표시되는지 확인

**절차**
1. 생산 라인 관리 → 생산 라인 목록

**기대 결과**
- 라인 ID, 주문 ID, 라인명, 상태, 진행률이 표시됨
- `data/production_lines.json`의 레코드 수와 일치

---

### TC-02-2 진행률 갱신

**목적**: RUNNING 상태 라인의 진행률이 정상 갱신되는지 확인

**전제 조건**: RUNNING 상태 생산 라인 존재 (TC-01-2 이후 start 처리 필요)

**절차**
1. 생산 라인 관리 → 진행률 갱신
2. RUNNING 상태 라인 ID 입력
3. 진행률 50 입력

**기대 결과**
- 갱신 성공 메시지 표시
- 해당 라인의 progress가 50으로 변경됨
- `data/production_lines.json` 반영됨

---

### TC-02-3 일시중지 / 재개

**목적**: 생산 라인 일시중지 및 재개가 정상 동작하는지 확인

**전제 조건**: RUNNING 상태 생산 라인 존재

**절차 (일시중지)**
1. 생산 라인 관리 → 일시중지
2. RUNNING 라인 ID 입력

**기대 결과 (일시중지)**
- 해당 라인 status가 PAUSED로 변경됨
- progress 값은 변화 없음

**절차 (재개)**
1. 생산 라인 관리 → 재개
2. PAUSED 라인 ID 입력

**기대 결과 (재개)**
- 해당 라인 status가 RUNNING으로 변경됨

---

### TC-02-4 생산 완료 처리 및 재고 증가 확인

**목적**: 생산 완료 시 재고가 수율 공식에 따라 정확히 증가하는지 확인

**전제 조건**
- RUNNING 상태 생산 라인 존재 (orderId=X)
- 주문 X의 quantity=10, 연결 시료의 yield=80.0

**절차**
1. 완료 전 시료 재고 기록 (stock=5 가정)
2. 생산 라인 관리 → 생산 완료 처리
3. RUNNING 라인 ID 입력

**기대 결과**
- 라인 status → DONE, progress → 100
- 재고 증가량 = floor(10 × 80.0 / 100.0) = 8
- 시료 stock: 5 + 8 = 13
- 주문 X status → CONFIRMED
- 모니터링 → 시료 재고 현황에서 변경된 stock 확인
- `data/production_lines.json`, `data/orders.json`, `data/samples.json` 모두 반영

---

### TC-02-5 DONE 상태 라인 진행률 갱신 시도 (거부)

**목적**: 종단 상태(DONE) 라인의 변경 불가 확인

**전제 조건**: DONE 상태 생산 라인 존재

**절차**
1. 생산 라인 관리 → 진행률 갱신
2. DONE 라인 ID 입력, 진행률 90 입력

**기대 결과**
- 오류 메시지 표시
- progress 변화 없음 (100 유지)

---

## TC-03 출고 테스트

### TC-03-1 정상 출고 처리

**목적**: CONFIRMED 주문의 출고가 정상 처리되고 재고가 차감되는지 확인

**전제 조건**
- CONFIRMED 상태 주문 존재 (orderId=Y, quantity=8)
- 연결 시료의 stock >= 8

**절차**
1. 완료 전 시료 재고 기록 (stock=13 가정)
2. 출고 관리 → 출고 처리
3. CONFIRMED 주문 ID 입력

**기대 결과**
- 출고 성공 메시지 표시
- 시료 stock: 13 - 8 = 5
- 주문 Y status → RELEASED
- 출고 이력에 Shipment 레코드 추가됨
- `data/shipments.json` 신규 레코드 존재
- `data/samples.json`, `data/orders.json` 반영

---

### TC-03-2 재고 부족 시 출고 거부

**목적**: 재고보다 많은 수량을 출고하려 할 때 거부되는지 확인

**전제 조건**
- CONFIRMED 상태 주문 존재 (quantity=100)
- 연결 시료의 stock < 100 (예: stock=5)

**절차**
1. 출고 관리 → 출고 처리
2. 해당 주문 ID 입력

**기대 결과**
- 재고 부족 오류 메시지 표시
- 주문 status 변화 없음 (CONFIRMED 유지)
- 시료 stock 변화 없음
- `data/shipments.json` 변화 없음

---

### TC-03-3 RESERVED 주문 출고 시도 (거부)

**목적**: CONFIRMED 이외 상태 주문 출고 시도 거부 확인

**전제 조건**: RESERVED 상태 주문 존재

**절차**
1. 출고 관리 → 출고 처리
2. RESERVED 주문 ID 입력

**기대 결과**
- 오류 메시지 표시 (CONFIRMED 상태만 출고 가능)
- 주문 상태 변화 없음, 재고 변화 없음

---

### TC-03-4 출고 이력 조회

**목적**: 출고 이력이 정상 표시되는지 확인

**절차**

**기대 결과**
- 출고 ID, 주문 ID, 시료명, 수량, 고객사, 출고일자 표시
- `data/shipments.json`의 레코드 수와 일치

## TC-04 JSON Persistence 테스트

### TC-04-1 프로그램 재시작 후 데이터 복원

**목적**: JSON 파일 기반 영속화가 정상 동작하는지 확인

**전제 조건**: 일부 주문, 시료, 출고 데이터가 존재하는 상태

**절차**
1. 현재 주문 목록의 ID 목록과 상태를 메모한다.
2. 프로그램을 종료한다. (`0. 종료` 선택)
3. 프로그램을 재시작한다.
4. 주문 관리 → 주문 목록 조회

**기대 결과**
- 종료 전과 동일한 주문 목록이 표시됨
- ID, 상태, 수량이 모두 일치함

---

### TC-04-2 시료 재고 변경 후 재시작 복원

**목적**: 재고(stock) 변경이 파일에 반영되고 재시작 후 복원되는지 확인

**전제 조건**: TC-02-4 완료 (생산 완료로 재고 변경됨)

**절차**
1. 현재 특정 시료의 stock 값을 기록한다.
2. 프로그램을 종료 후 재시작한다.
3. 모니터링 → 시료 재고 현황 조회

**기대 결과**
- 재시작 후에도 변경된 stock 값이 그대로 표시됨

---

### TC-04-3 nextId 단조 증가 확인

**목적**: 레코드 삭제 후 재생성 시 ID가 재사용되지 않는지 확인

**절차**
1. 주문 목록에서 마지막 주문 ID(예: N)를 확인한다.
2. 해당 주문을 취소(REJECTED)한다.
3. 새 주문을 생성한다.

**기대 결과**
- 새 주문의 ID가 N+1 이상 (N 재사용 없음)

## 전체 흐름 통합 테스트 (시나리오)

### FULL-01 주문 → 생산 → 출고 전체 흐름

다음 순서를 중단 없이 완주한다.

| 단계 | 동작 | 확인 사항 |
|------|------|----------|
| 1 | 시료 ID=1로 주문 5건 생성 | orders.json에 RESERVED 5건 추가 |
| 2 | 주문 1건에 생산 시작 | PRODUCING 전환, ProductionLine IDLE 생성 |
| 3 | 해당 라인 진행률 30 갱신 | progress=30 반영 |
| 4 | 진행률 80 갱신 | progress=80 반영 |
| 5 | 생산 완료 처리 | DONE, 재고 증가, 주문 CONFIRMED |
| 6 | CONFIRMED 주문 출고 처리 | 재고 차감, RELEASED, shipments.json 추가 |
| 7 | 모니터링 대시보드 확인 | RELEASED 1건 집계, 시료 재고 정확 |
| 8 | 프로그램 재시작 | 모든 상태 복원 확인 |

**전체 통과 조건**: 8단계 모두 기대 결과와 일치하면 PoC 완료 조건 달성
